**화면은 세 개입니다. A "무슨 결정?"에서 카드를 누르면 쌓기로 B로 가고, B 안에서는 옵션과 결정 방식을 탭으로 옆으로 넘기고, 「골라줘!」를 누르면 C 결과 시트가 아래에서 덮입니다.**

`[👉 대표 화면 C 캡처 + 요소 분석 표]`
**대표 화면은 C 결과 시트입니다.**
**C-2 진행 막대는 P01, 지금 몇 단계인지 보여 줍니다.**

**C-7 결정 잠금은 P03, 잠가도 다시 풀 수 있고, C-8은 세 번째 다시에서 STOP 배너를 띄우는 P05입니다.**

## Q&A 대비 — 질문별 답 (근거 장)

**Q1. 그냥 랜덤 휠 앱이랑 뭐가 다른가요?**
**세 가지가 다릅니다. 입력이 0번인 상황 템플릿, 비교를 쉬운 게임으로 바꾼 결정 방식, 그리고 결과를 받아들이고 멈추게 하는 후회 테스트 · 반전 · 잠금입니다. 근거는 04장과 리뷰 유형 ①과 ③입니다.**
(中) 免输入模板 + 游戏化 + 让人接受并停下。

**Q2. 결과가 미리 정한 값이면 사용자를 속이는 것 아닌가요?**
**이번 과제는 UI 프로토타입이라 실제 추천 로직은 감점 항목입니다. 그래서 C 맨 아래에 "예시 결과, 실제 추천 로직 없음"을 항상 표시했고, 셀프 논증 쟁점 3에서 이 문제를 다뤘습니다.**
(中) 规则禁止真实算法,画面写明"예시",셀프논증第3点。

**Q3. 기능이 많은데 선택장애 사용자에게 오히려 복잡하지 않나요?**
**그래서 쟁점 6에서 스스로 반론했습니다. 기본 경로는 항상 탭 세 번이고, 결정 방식은 네 개만 보이며 추천이 미리 선택돼 있습니다. 나머지는 「더 많은 방법 보기」를 눌러야만 보입니다. P08 미니멀입니다.**
(中) 默认只 4 种+推荐预选,其余折叠。

**Q4. 친구 투표나 결정 지갑은 실제로 저장하거나 보내나요?**
**아닙니다. 친구 표와 지난 결정은 db.json에 미리 넣은 예시를 GET으로 보여 주고, 「친구 부르기」는 "예시" SnackBar만 띄웁니다. 내 하트나 잠금은 setState로 화면 안에서만 바뀌고 저장하지 않습니다. 실제 저장은 STATE 주석 S3, S5, S6으로 표시만 했습니다.**
(中) 全是预设数据 + setState,不保存不发送,只做 STATE 注释。

**Q5. 가위바위보는 앱이 이긴 사람을 정하나요?**
**아니요. 판정도 계산 로직이 될 수 있어서, 앱은 두 사람의 손을 동시에 공개만 하고 승패는 둘이 직접 정합니다.**

**Q6. 왜 화면이 세 개뿐인가요? 결정 지갑은 새 화면 아닌가요?**
**과제가 디자인 가이드에 없는 화면을 감점하기 때문에 세 화면만 만들었습니다. 결정 지갑은 새 화면이 아니라 A 화면 안의 섹션이고, 디자인 가이드에 A-10으로 적혀 있습니다.**

**Q7. 리뷰 건수는 어떻게 셌나요?**
**Google Play에 보이는 리뷰 약 190개를 직접 읽고 유형별로 분류했습니다. 스토어에 별점 분포 그래프가 보이지 않아서, 분포는 별점이 확인되는 인용 리뷰를 표본으로 적었습니다.**
