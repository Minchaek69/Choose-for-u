## 4. 피쉬본 · 5 Why

**머리(문제):** 결과가 나와도 받아들이지 못하고 다시 돌리기를 반복한다.

| 시각 | 원인 |
|---|---|
| 모바일 UX | 결과 화면에 "다시 돌리기"만 크게 있다 — 멈추는 버튼(확정)이 없다 |
| 사용성 | 옵션을 매번 입력 → 결과 볼 때 이미 지쳐 있다 (리뷰 ①) |
| 데이터 | 결과에 이유(왜 이것인지)가 없다 |
| API | 상황별 옵션 · 이유 데이터를 받아 오지 않는다 (전부 사용자 입력) |
| 네트워크 | 오프라인 앱 — 기기 간 가져오기 실패 (Android · iOS 차이, 리뷰 #1) |
| 프로세스 | 결정 과정이 "돌리기 1단계"뿐 — 비교·제거·확인 단계가 없다 |

**우선순위 1개: 모바일 UX** — 리뷰 유형 ③과 저니 최저점이 같은 곳을 가리키고, 데이터 없이 **UI만으로 고칠 수 있다**.

| Why | 답 |
|---|---|
| Why 1 왜 다시 돌리나? | 결과가 마음에 안 들어서 |
| Why 2 왜 마음에 안 드나? | 결과가 "그냥 랜덤"이라 내 선택이라고 느껴지지 않아서 |
| Why 3 왜 내 선택 같지 않나? | 결정 과정에 내가 참여한 단계(비교·제거·반응)가 없어서 |
| Why 4 왜 그 단계가 없나? | 앱이 "결과를 내는 것"을 목표로 설계돼, 결과 뒤 행동(확정·멈춤)을 설계하지 않아서 |
| Why 5 왜 결과 뒤를 설계하지 않았나? | 선택장애의 진짜 문제를 "선택지 부족"으로 보고 "결정을 받아들이는 것(허락)"으로 보지 않아서 |

**근본 원인 → v2에서 고칠 것:** 결과를 *받아들이고 멈추는* 단계가 없다
→ C-6 후회 테스트(P06) · C-5 수용 카피(P02) · C-7 결정 잠금(P03) · C-8 3번째 STOP 배너(P05) · B-6 게임 선택(P07)
